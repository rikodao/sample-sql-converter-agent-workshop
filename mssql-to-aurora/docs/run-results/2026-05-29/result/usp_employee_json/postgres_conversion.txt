KEY TRANSFORMATIONS
============================================================================

1. FOR JSON PATH → jsonb_build_object() + jsonb_agg()
   ----------------------------------------------------------
   T-SQL:
     SELECT col1, col2, ... FOR JSON PATH
   
   PostgreSQL:
     SELECT jsonb_agg(
       jsonb_build_object(
         'col1', col1,
         'col2', col2,
         ...
       )
     )

2. WITHOUT_ARRAY_WRAPPER → Single Object Subquery
   ----------------------------------------------------------
   T-SQL:
     (SELECT ... FOR JSON PATH, WITHOUT_ARRAY_WRAPPER) AS nested_obj
   
   PostgreSQL:
     (SELECT jsonb_build_object(...)) AS nested_obj

3. Parameter Naming
   ----------------------------------------------------------
   T-SQL:
     @employee_id INT = NULL
     @department_id INT = NULL
     @include_inactive BIT = 0
   
   PostgreSQL:
     p_employee_id INT DEFAULT NULL
     p_department_id INT DEFAULT NULL
     p_include_inactive boolean DEFAULT false

4. Error Handling
   ----------------------------------------------------------
   T-SQL:
     RAISERROR('Invalid employee_id. Must be a positive integer.', 16, 1);
     RETURN;
   
   PostgreSQL:
     RAISE EXCEPTION 'Invalid employee_id. Must be a positive integer.';

5. String Concatenation
   ----------------------------------------------------------
   T-SQL:
     m.first_name + ' ' + m.last_name
   
   PostgreSQL:
     m.first_name || ' ' || m.last_name

6. Boolean Type

     boolean (true/false)

1. Native jsonb type is more efficient than T-SQL's NVARCHAR(MAX)
2. jsonb supports indexing and operators (->, ->>)
3. Better JSON manipulation functions (jsonb_set, jsonb_insert, etc.)
4. Automatic validation of JSON structure

Known Differences:
------------------
1. Return mechanism:
   - T-SQL: Returns result set directly
   - PostgreSQL PROCEDURE: Cannot return result sets
   - PostgreSQL FUNCTION: Returns jsonb value (recommended)

2. Error handling:
   - T-SQL: RAISERROR + RETURN
   - PostgreSQL: RAISE EXCEPTION (automatically exits)

3. Boolean representation:
   - T-SQL: BIT (0/1) in JSON output
   - PostgreSQL: boolean (true/false) in JSON output
   - Note: This is a cosmetic difference; both are valid JSON
