============================================================
KNOWN LIMITATIONS & WORKAROUNDS
============================================================

1. Case Sensitivity:
   Problem: PostgreSQL is case-sensitive by default
   Workaround: If case-insensitive matching is required:
   
   -- Option A: Normalize to lowercase
   WHERE LOWER(e.status) = 'active'
   
   -- Option B: Use ILIKE for pattern matching
   WHERE e.status ILIKE 'active'
   
   -- Option C: Specify collation
   WHERE e.status COLLATE "en_US.utf8" = 'Active'

2. Boolean vs BIT:
   Problem: SQL Server uses BIT (0/1), PostgreSQL uses BOOLEAN
   Workaround: Already handled in conversion (= 1 → = true)
   Note: PostgreSQL BOOLEAN also accepts 0/1 as input

3. Date Functions:
   Problem: Original comments reference GETDATE()
   Workaround: Use now() or CURRENT_DATE in PostgreSQL
   Example: WHERE e.end_date > CURRENT_DATE
