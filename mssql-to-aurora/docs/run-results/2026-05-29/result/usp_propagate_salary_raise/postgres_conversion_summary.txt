============================================================================
BEHAVIORAL DIFFERENCES
============================================================================

1. RESULT SET RETURN
   - T-SQL: Procedures can return result sets via SELECT
   - PostgreSQL: Procedures cannot return result sets
   - Solution: Use INOUT parameters for output values
   - Alternative: Convert to FUNCTION RETURNS TABLE if result set is required

2. TRANSACTION SCOPE
   - T-SQL: Explicit BEGIN TRANSACTION / COMMIT required
   - PostgreSQL: Procedures run in implicit transaction
   - Impact: Automatic rollback on exception, no need for @@TRANCOUNT check

3. ERROR INFORMATION
   - T-SQL: ERROR_SEVERITY() and ERROR_STATE() available
   - PostgreSQL: Only MESSAGE_TEXT and SQLSTATE available
   - Impact: Less detailed error information in PostgreSQL

4. TEMPORARY TABLE SCOPE
   - T-SQL: #temp tables scoped to session, auto-dropped on disconnect
   - PostgreSQL: TEMP tables scoped to session, persist until explicit drop
   - Solution: Explicit DROP TABLE IF EXISTS for clean state

5. DATE ARITHMETIC
   - T-SQL: DATEDIFF(DAY, a, b) returns integer
   - PostgreSQL: (b::date - a::date) returns integer
   - Impact: Same result, different syntax
