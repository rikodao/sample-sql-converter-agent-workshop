CREATE PROCEDURE dbo.usp_dynamic_count_with_output
    @table_name SYSNAME,
    @filter_column SYSNAME,
    @filter_value NVARCHAR(200),
    @row_count INT OUTPUT
AS
BEGIN
    SET NOCOUNT ON;
    DECLARE @sql NVARCHAR(MAX);
    SET @sql = N'SELECT @cnt = COUNT(*) FROM ' + QUOTENAME(@table_name)
        + N' WHERE ' + QUOTENAME(@filter_column) + N' = @val';

    EXEC sp_executesql @sql,
        N'@val NVARCHAR(200), @cnt INT OUTPUT',
        @val = @filter_value,
        @cnt = @row_count OUTPUT;
END
---

HYPOTHESIS ON DIFFERENCES:
---
The TRY-CATCH limitation with sp_executesql is a known Babelfish behavior.
In SQL Server, TRY-CATCH can catch errors from dynamic SQL executed via
sp_executesql. In Babelfish, the error handling model differs slightly:
- Compile-time errors in dynamic SQL are caught during sp_executesql execution
- Runtime errors propagate through the call stack differently
- This is due to the underlying PostgreSQL error handling mechanism

This is documented in Babelfish limitations and is consistent with the
"sp_executesql + OUTPUT parameter" partial support category mentioned in
the known limitations list.
