BABELFISH LIMITATION IDENTIFIED
============================================================================

Feature: PIVOT with Column Aliases in ORDER BY
Support Level: PARTIAL (DDL OK, Runtime Limited)

Known Issues:
1. Column alias resolution after PIVOT fails at runtime
2. ORDER BY cannot reference columns from PIVOT source subquery
3. Error message incorrectly references original column name, not alias
4. Issue affects both stored procedures and direct queries

Workaround Required:
- Rewrite using CASE expressions with GROUP BY
- Avoid PIVOT syntax in Babelfish
- Use standard SQL aggregation instead

Example Workaround:
------------------
SELECT
    d.name AS department_name,
    COUNT(CASE WHEN e.is_active = 1 THEN e.employee_id END) AS Active,
    COUNT(CASE WHEN e.is_active = 0 THEN e.employee_id END) AS Inactive
FROM dbo.departments d
LEFT JOIN dbo.employees e ON d.department_id = e.department_id
GROUP BY d.name
ORDER BY d.name;

This approach produces identical results without using PIVOT syntax.
