## 4. ROOT CAUSE ANALYSIS

### Primary Issue: OUTPUT Parameter Limitation in Babelfish TDS Protocol

The error occurs when attempting to call a stored procedure with OUTPUT parameters through the Babelfish TDS (Tabular Data Stream) endpoint. This is a known limitation in Babelfish's T-SQL compatibility layer.

### Technical Details:

1. **DDL Compatibility**: ✅ PASS
   - The procedure definition with OUTPUT parameter is accepted
   - FOR JSON PATH with WITHOUT_ARRAY_WRAPPER is supported
   - Syntax is fully compatible

2. **Runtime Compatibility**: ❌ FAIL
   - OUTPUT parameters cannot be properly bound through the TDS protocol
   - The ODBC driver reports that the argument is "not writable"
   - This affects both direct calls and calls from within other procedures

3. **Known Babelfish Limitations Identified**:
   - **OUTPUT Parameters via TDS**: Babelfish's TDS endpoint has limited support for OUTPUT parameters when called from external clients
   - **FOR JSON PATH**: While the syntax is accepted, the actual JSON generation behavior may differ from SQL Server
   - **sp_executesql with OUTPUT**: Dynamic SQL with OUTPUT parameters has additional constraints

### Affected Features:
- ✅ CREATE PROCEDURE with OUTPUT parameter (syntax accepted)
- ✅ FOR JSON PATH, WITHOUT_ARRAY_WRAPPER (syntax accepted)
- ✅ INNER JOIN with table aliases
- ✅ SET NOCOUNT ON
- ❌ EXEC procedure with OUTPUT parameter binding (runtime failure)
- ❌ OUTPUT parameter value retrieval from external calls

## 5. HYPOTHESIS

The stored procedure `dbo.usp_employee_json` uses an OUTPUT parameter to return JSON data. While Babelfish accepts the DDL and creates the procedure successfully, the TDS protocol implementation in Babelfish does not fully support OUTPUT parameter binding when the procedure is invoked from an external client (ODBC/JDBC).

This is a **protocol-level limitation** rather than a T-SQL syntax incompatibility. The procedure definition is valid, but the execution model differs from SQL Server.

### Comparison with SQL Server:
- **SQL Server**: OUTPUT parameters are fully supported through TDS protocol, allowing external clients to bind variables and retrieve output values
- **Babelfish**: OUTPUT parameters are partially supported; they work within T-SQL batches but fail when called through the TDS endpoint with parameter binding

### Related Known Issues:
1. **sp_executesql + OUTPUT**: Similar limitations exist with dynamic SQL
2. **Table-Valued Parameters (TVP)**: Also have limited support in Babelfish
3. **RETURN values**: May have similar binding issues
